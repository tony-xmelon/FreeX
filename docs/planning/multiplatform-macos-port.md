# Multiplatform Port Plan: macOS First

**Last updated:** 2026-06-08

FreeX v1 is intentionally a native Windows desktop app built on WPF. ADR-001 accepted that WPF is Windows-only and deferred cross-platform delivery, while preserving optionality by keeping the workbook model, formula engine, command layer, calculation layer, and file adapters UI-independent.

This plan records the macOS-first multiplatform preparation path and the current Avalonia preview-app status.

## Current State

- `Core.Model`, `Core.Formula`, `Core.Calc`, `Core.Commands`, and `Core.IO` target plain `net10.0`.
- `App.Host`, `App.UI`, UI tests, and several interop tools target `net10.0-windows` and use WPF.
- The documented architecture already keeps core projects from referencing app projects.
- `FreeX.DefaultTests.slnx` contains the non-UI test lane and is the first practical macOS validation target.
- `src/FreeX.App.Avalonia` is the active macOS-capable preview shell, backed by shared app services and portable core projects.
- The `macOS App Preview` workflow now packages architecture-specific app artifacts and records hosted packaging, LaunchServices, Open-With launch, smoke, checksum, diagnostics, and distribution-candidate evidence.
- Excel COM smoke/fidelity tools remain Windows-only and should stay in Windows lanes.

## GitHub Actions macOS Validation

GitHub-hosted macOS runners can be used even without a local Mac. They now cover the portable engine lane and the Avalonia app-bundle preview lane. The portable lane should stay focused on engine readiness:

```yaml
runs-on: macos-latest
```

The CI job should:

1. Checkout the repository.
2. Install `.NET 10` through `actions/setup-dotnet`.
3. Build `FreeX.DefaultTests.slnx` in Release.
4. Test `FreeX.DefaultTests.slnx` in Release with `--no-build`.

This lane is intentionally limited to portable projects. It must not build `FreeX.slnx`, `FreeX.UiTests.slnx`, `App.Host`, `App.UI`, or WPF/COM tools.

## Preparation Work

1. **Keep the core portable.** Add or maintain source guards that prevent `System.Windows`, `Microsoft.Win32`, WinRT, COM, and WPF package references from entering `Core.*`.
2. **Extend the app-service boundary.** Continue moving platform-specific file dialogs, clipboard, drag/drop, hyperlink launch, app data paths, dispatching, window management, sharing, printing/export, crash reporting, and accessibility metadata behind service interfaces.
3. **Keep reusable app logic out of WPF.** Continue extracting workbook session orchestration, command routing, menu/ribbon command models, dialog planners, options, localization, and non-visual state into shared app layers.
4. **Separate rendering models from renderers.** Keep viewport, chart, print, icon, and drawing-object layout decisions platform-neutral, then maintain WPF and macOS renderers separately.
5. **Evaluate Avalonia as the first macOS UI stack.** Avalonia is the active first candidate because it is desktop-first, XAML/C# friendly, and targets macOS, Windows, and Linux. MAUI remains a possible alternative, but its macOS path is Mac Catalyst and should be evaluated against spreadsheet-grid fidelity before committing.
6. **Keep Windows fidelity lanes.** Desktop Excel COM open/save/reopen, chart interop comparison, WPF UI automation, PDF/XPS export through WPF, and tester-release packaging remain Windows validation lanes until equivalent macOS-specific tools exist.

## First Port Milestones

1. **Portable CI gate:** macOS GitHub Actions builds and tests `FreeX.DefaultTests.slnx`.
2. **Avalonia preview shell:** `src/FreeX.App.Avalonia` starts, loads startup/open-with/dragged local workbooks through shared open paths, and renders a workbook viewport from portable services.
3. **Grid renderer spike:** continue proving scrolling, selection, cell text, row/column headers, freeze panes, and drawing-object preview bounds in Avalonia.
4. **Service abstraction pass:** replace direct WPF/Windows calls in reusable host logic with platform-service interfaces. `src/FreeX.App.Services` now holds the shared adapter catalog, default workbook factory, startup workbook loader, portable workbook open/save services, workbook session orchestration, active-sheet and selected-range state, multi-range-aware selected-range status statistics calculation/formatting, cell-entry parsing, single-cell edit orchestration with Undo/Redo history and grouped-sheet propagation, AutoSum formula planning/insertion, selected-range clipboard text copy/cut with an explicit multi-range guard, internal normal paste with formula/style payloads, non-overlapping cut-source clearing, Paste Special column-width/metadata/paste-link/copied-range picture orchestration, image paste orchestration, and grouped-sheet propagation across those paste routes, plain-text external paste orchestration with grouped-sheet propagation, selected-range Clear All/Formats/Contents/Comments and Notes/Hyperlinks orchestration with grouped-sheet propagation, directional Fill Down/Right/Up/Left orchestration with grouped-sheet propagation, Format Painter source capture/application/cancel state, selected-range font-size grow/shrink with fitting row-height updates, selected-range fill/font color formatting, selected-range horizontal/vertical alignment, wrap text, indent increase/decrease, text orientation/rotation command orchestration, Cell Styles preset planning/application, selected-range border preset planning/application, number-format/decimal-place orchestration, formula scanning, text-import open normalization, and non-mutating Data Validation preview planning used by the Avalonia shell and WPF host adapters. `src/FreeX.Core.Calc` now owns the shared text-orientation render geometry planner consumed by both WPF and Avalonia.
5. **macOS packaging workflow:** GitHub Actions publish jobs for `osx-arm64` and `osx-x64` app artifacts are integrated, including internal-preview evidence plus a guarded distribution-candidate contract.

## macOS Command-Key/Menu Readiness

The Avalonia preview shell should treat macOS Command-key shortcuts as first-class native menu gestures while preserving the shared Windows-style Ctrl routes that still matter for spreadsheet parity and cross-platform testing. The current source guard in `tests/FreeX.App.Services.Tests/AvaloniaShellSourceTests.cs` verifies that native menu items expose Command gestures for New, Open, Save, Save As, Close Workbook, Undo, Redo, Cut, Copy, Paste, Paste Special, Select All, Find, Find Next, Bold, Italic, Underline, Format Cells, and Quit. It also verifies that direct input routes use the shared command-modifier helpers for sheet switching, Find, Select All, Bold, Italic, Underline, and Close Workbook so either Ctrl or Command can reach the same workbook/session behavior without accepting unrelated extra modifiers.

Hosted LaunchServices smoke now proves that the native menus and menu items are present through `native_*` evidence keys and that the packaged runtime menu model carries representative Command-key gestures through `command_key_smoke=passed`, `command_key_smoke_attempted=true`, `cmd_new_workbook_menu_gesture=true`, `cmd_open_menu_gesture=true`, `cmd_save_menu_gesture=true`, `cmd_save_as_menu_gesture=true`, `cmd_close_workbook_menu_gesture=true`, `cmd_quit_menu_gesture=true`, `cmd_select_all_menu_gesture=true`, `cmd_find_menu_gesture=true`, `cmd_bold_menu_gesture=true`, `cmd_italic_menu_gesture=true`, and `cmd_underline_menu_gesture=true`. It does not replace hosted macOS runner evidence for `plutil`, apphost architecture, signing, notarization, LaunchServices activation, or runtime smoke.

This is a preview artifact, not a release channel. Remaining blockers are:

- Public distribution still needs a successful `distribution_candidate=true` hosted run with Developer ID signing, accepted notarization, stapler validation, and attached evidence for both runtimes.
- Human macOS proof is still needed for Finder double-click/default-handler behavior, Gatekeeper launch, and live OS Command-key behavior.
- Format Cells still needs hosted apply/save-reopen evidence plus fuller WPF/Avalonia parity beyond the compact first-pass apply controls.
- Data Validation still needs fuller mutation parity beyond Paste Special metadata transfer.
- Public-preview readiness still needs accessibility evidence, including keyboard-only and VoiceOver validation on real macOS hardware.
- Broader parity remains for full drawing-object editing, full WPF clipboard semantics including actual multi-range copy/paste, WPF ribbon/task-pane/backstage F6 focus breadth, and color picker/remembered-color behavior beyond shared default palette swatches.

## Non-Goals For The First macOS Lane

- Building the current WPF app on macOS.
- Running WPF UI tests on macOS.
- Replacing Windows tester releases.
- Replacing Excel COM fidelity evidence.
- Claiming a user-ready macOS application before public-distribution, human macOS, and accessibility gates are complete.

## Success Criteria

- `FreeX.DefaultTests.slnx` passes on macOS Actions.
- The Windows default and UI lanes continue to pass.
- New shared app code can be exercised without WPF.
- The Avalonia preview shell can open, display, navigate worksheets, edit, and save representative workbooks without duplicating workbook-engine logic.
- The macOS packaging workflow remains tied to the Avalonia app project and records internal-preview versus distribution-candidate evidence clearly.
