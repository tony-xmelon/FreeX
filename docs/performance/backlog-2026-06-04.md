## Active Priority: XLSX Open/Save

Goal: move FreeX XLSX open/save closer to Excel while preserving the current fidelity contract, package-retention guarantees, and Excel openability smoke coverage.

Current constraints:

- `XlsxFileAdapter` still uses ClosedXML for workbook materialization and save, so large improvements may require bypassing ClosedXML in selected hot paths rather than tuning around it.
- XLSX save also performs package post-processing to retain native metadata. Optimizations must not weaken [formats/xlsx-corpus-report.md](../formats/xlsx-corpus-report.md) guarantees.
- Benchmark timing from xUnit microbenchmarks is noisy; allocation and repeated relative comparisons are more reliable than a single run.

Candidate work, in priority order:

1. Continue reducing XLSX open allocation/time in the measured hot phases: `closedxml_load`, `sheet_xml_layout`, and the remaining eager source patch baseline. The safest next source-snapshot slice is a lightweight open-time edit baseline or workbook revision tracker with a pre-edit materialization hook in the command path; fully lazy baseline creation is unsafe without that hook because first-save edits would be treated as original state.
2. Prototype a guarded streaming worksheet metadata reader for the high-cardinality XML surfaces that are still parsed into full `XDocument` instances before ClosedXML also loads them. The safe shape is to start with worksheet row/cell layout facts and preserve the existing `XDocument` path for sheets containing complex metadata until parity tests prove the streaming path.
3. Prototype a guarded ClosedXML bypass for style-only and other blank-format metadata only if app-level timing shows the compressed run store and streaming metadata reader are not enough. Keep ClosedXML for formulas/values initially, but feed modeled blank-format runs directly from sheet XML.
4. Re-run the app-shaped edited-save benchmark whenever new real-world slow workbooks appear and use `save_path`/`save_reason` to choose the next save slice. The current Partner Dashboard one-cell edit reaches `source_patch`; remaining XLSX save work should be driven by new fallback reasons rather than broad guard relaxation.
5. Extend package patching beyond scalar value/formula-text/new-cell/clear-cell/existing-style/dimension/merge/internal-hyperlink/legacy-note/structured-table-safe/chart-safe/pivot-safe edits. Highest-value next slices, in practical order, are shared/array formulas and richer worksheet metadata. New styles still need explicit `styles.xml` mutation and should remain fallback until that is guarded and benchmarked.
6. Split XLSX fallback saves further into ClosedXML workbook emission, modeled feature writers, native metadata merge/post-processing, package validation, and stream/file replacement when diagnostics show an unavoidable full save, then batch ZIP/XML post-processing where the timing shows repeated archive update passes dominate.
7. Continue folding feature-inspection/reporting into trusted package facts where the load path already inspected the same package entries; keep public `XlsxFeatureInspector.Inspect` behavior intact for standalone callers and corpus warnings.
8. Compare `.fxl`, CSV, and SpreadsheetML after XLSX has a broader deterministic fixture set, but keep XLSX first.

## Remaining Cross-App Backlog

These items remain valid but are behind XLSX IO for now:

- **App.UI drawing-object repainting:** consider bitmap or frozen-layer caching for stable drawing-object layers. This needs careful invalidation and visual-regression coverage.
- **App.Host viewport batching:** batch vertical/horizontal scroll reveal updates so a single offscreen navigation does not trigger duplicate viewport refresh work. Split panes and side-by-side sync make this medium risk.
- **Core.Commands dense undo paths:** row/column shift undo can likely move existing cells back instead of re-materializing all shifted `CellStateSnapshot` instances. This is correctness-heavy because undo history and formula restore ordering are involved.
- **Core.Calc conditional-format formulas:** cache more static formula results for viewport conditional formatting. Volatile functions, current-cell-sensitive formulas, structured references, and relative references need strict guards.
- **Core.IO non-XLSX formats:** SpreadsheetML and CSV have measurable load/save work remaining, but XLSX is the priority because it carries the compatibility burden.

## Guardrails

- Keep every optimization benchmark-backed.
- Prefer deterministic fixtures before private workbook measurements.
- Preserve Excel openability, package-health, and corpus-retention tests.
- Reject changes that only reduce allocation while worsening wall-clock time on the priority scenario.
- Integrate small, verified slices rather than accumulating a large IO branch.
