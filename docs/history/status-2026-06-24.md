# FreeX Status - 2026-06-24

Report scope: documentation refresh, repository hygiene, and current `origin/main` state as of 2026-06-24. This snapshot anchors the 2026-06-24 tester-release candidate verification session.

Mainline observed: branch-neutral `origin/main` snapshot at `2cc46959a` after the June 24 format-adapter and documentation refresh.

## Summary

FreeX remains in late-stage fidelity and release hardening. Since the June 21 snapshot the following areas advanced:

- **Spreadsheet file-format adapters**: `.xlsm`/`.xltm` macro-enabled packages now support full read/write (previously open-only); a `.prn` formatted-text (space-delimited) adapter was added; a `.mht`/`.mhtml` single-file web-page adapter was added; and a read-only tabular-data import from PDF was implemented via PdfPig grid extraction.
- **PivotTable visual fidelity**: an intensive workstream through 2026-06-23 and 2026-06-24 (documented across 20+ fidelity records) resolved palette routing, stripe fill, grand-total column, and border edge cases across `PivotStyleMedium8`, `Medium10`, `Medium12`, `Medium13`, `Light9`, `Light14`, and related themes. This is an ongoing fidelity workstream rather than a closed gate.
- **Shared design-token theming (WS-G)**: `Free.Shared.Theme` (WPF and Avalonia appliers, brand themes) landed in two rounds; the WPF title bar and Avalonia status surface are now token-driven and runtime-swappable. The theming merge introduced a macOS-readiness preflight gap (see below) that was resolved in this session.
- **FreeW (sibling .docx app)**: substantial format-surface work — legacy `.doc`/`.dot` binary WRITE, Strict OOXML read/write, Word-2003 WordML writer, HTML Web Page/Filtered save variants, improved PDF import fidelity, plus multiple Word-parity ribbon waves (tables, charts, pictures, shapes, SmartArt, watermark, find wildcards, section breaks).

The latest verified tester release found through the GitHub Releases API is **v0.8.127**, published on 2026-06-20 from Tester Release run 127 attempt 1 at commit `1790d2abdc7112047382c3f19fcb417eb0227059`. The current session is preparing the next tester release off the 2026-06-24 `origin/main` HEAD. It is still an internal tester release, not a public-preview promotion, because live keyboard-only, screen-reader, UI Automation catalog, and known-issues accessibility evidence must be recorded for public-preview eligibility.

### This Session — Resolved Release-Gate Fixes

Each of these was an incomplete-merge breakage left on the integrated tree by parallel sessions; all surfaced during this session's full-gate run and were reconciled so the tester-release gate is green:

- **Stale Medium13 PivotTable style test**: `PivotLoadedStyleApplicationTests.ApplyLoadedPivotStyles_StylesMedium13TabularOuterRowLabelsAndBodyGrid` still expected the Medium13 striped-row fill at Accent5 tint 0.9, but production was updated to the Excel-sampled tint 0.85; sibling tests had been updated and this one was missed. Fixed by aligning the test expectations to 0.85.
- **Stale title-bar branding hygiene test**: `MainWindowSourceHygieneTests.MainWindow_UsesVisibleFreeXBrandingAndWindowIcon` still asserted the title-bar background bound via `StaticResource`, but WS-G round 2 made the title bar token-driven and runtime-swappable (`DynamicResource FreeXTitleBarBrush`). Fixed by updating the test to the `DynamicResource` contract; branding glyphs and the brush key are unchanged.
- **Missing third-party notices rows**: the read-only PDF import feature added the `UglyToad.PdfPig.{Core,Fonts,Tokenization,Tokens}` packages, which were not listed in `THIRD_PARTY_NOTICES.md`, failing `ThirdPartyNoticeTests.ThirdPartyNotices_ListEveryRestoredNuGetPackage`. Fixed by adding the four Apache-2.0 rows and refreshing the restored-package count.
- **macOS-readiness preflight gap** (resolved on `origin/main` by a parallel session in commit `caeef1c55`): `tools/Test-MacOsAppReadiness.ps1` portable allowlist was missing `Free.Shared.Theme.Avalonia` from the WS-G theming merge, leaving the macOS-readiness preflight gate red even though the C# guard test already listed the project. Now green on the integrated tree.
