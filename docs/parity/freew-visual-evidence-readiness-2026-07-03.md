# FreeW Visual Evidence Readiness - 2026-07-03

## Slice

After the backstage print evidence readiness slice, the combined FreeW visual evidence summary now emits deterministic backstage print readiness in both structured JSON and Markdown. The JSON field is `BackstagePrintEvidenceReadiness`; the Markdown view is the `Backstage Print Evidence Readiness` table generated by `FreeWVisualEvidenceManifestNormalizer.ToMarkdown`.

Both outputs cover the required WPF/Avalonia host pairs for:

- `backstage-print-preview-fidelity`
- `backstage-pdf-export-fidelity`

Each required host/page row reports `trusted`, `failed`, or `missing`, plus the normalized output path and the row-level failure reason when a capture exists but cannot be trusted.

The 2026-07-04 evidence-depth update tightened the same summary contract: Backstage print/export rows must also declare scenario-specific `backstageWorkflow` metadata. `backstage-print-preview-fidelity` rows must report `print-preview`, and `backstage-pdf-export-fidelity` rows must report `pdf-export`, so a real capture cannot be accidentally cross-wired between Print Preview and Create PDF evidence.

The 2026-07-05 print/export evidence hardening also requires real renderer capture sources for trusted backstage rows: WPF rows must declare `captureSource=wpf-composite-renderer`, and Avalonia rows must declare `captureSource=avalonia-render-target`. Software fallback, placeholder, or fallback capture metadata now fails the normalized row and produces an explicit `missing-real-captures` blocker instead of being counted as trusted print/export evidence.

The 2026-07-13 route hardening adds one more explicit capture contract: trusted Backstage rows must declare the scenario-specific `backstageCaptureRoute`. Print Preview rows use `backstage-print-preview-fixed-layout-capture`; PDF export rows use `backstage-pdf-export-raster-capture`. Generic route labels such as `workflow-only`, `screen-capture`, or `page-screenshot` fail the normalized row, so the summary cannot infer real Backstage print/export evidence from matching workflow and artifact labels alone.

The follow-up 2026-07-04 renderer-contract update extends compiled pair validation beyond backstage, section, review, drawing-object, and chart/SmartArt rows. Table scenarios now compare WPF/Avalonia table layout and pagination signatures, and field/reference scenarios now compare WPF/Avalonia field counts, field kinds, complex-field keywords, and header/footer field slots. This keeps shared visual evidence from passing on row counts when the semantic renderer contract has drifted between hosts.

The 2026-07-04 WordArt watermark contract-depth slice adds paired semantic validation for `wordart-picture-watermark-layout`. The normalizer now compares WPF/Avalonia page feature signatures for columns, page border, and picture watermark metadata, plus floating object and drawing-effect signatures, before trusting the paired visual evidence row.

The 2026-07-05 table signature triage update keeps the table pair-signature failure intact but makes it actionable. When WPF/Avalonia table plan signatures differ, the summary now includes bounded field-level details such as table style drift, `HasCellShading` drift, and exact cell coordinates like `r0c0g0 shading color` before the raw signatures. Current paired evidence shows the table family failing on header-cell shading metadata, while broader drawing and SmartArt mismatches remain separate lanes.

The 2026-07-13 equation geometry evidence slice adds a shared, no-Word equation contract for `equation-structures`. `FreeWVisualEvidencePlanner` now emits `Equations` metadata for each page expectation, including equation/element/segment counts, element-kind counts, segment-role counts, baseline-role counts, nested slot counts/max depth, and deterministic segment, element, and slot geometry signatures. The signatures cover scripts, fractions, radicals with degree/radicand, n-ary limits/operand, matrix and equation-array cells, decorators, delimiters, group characters, and function application. `FreeWVisualEvidenceManifestNormalizer` surfaces the same facts in summary JSON and the `Equation Geometry Evidence` Markdown table, and the WPF/Avalonia pair validator fails if either host omits the metadata or if any count/signature drifts. This remains shared FreeW renderer evidence only; it does not claim authoritative Microsoft Word PNG equation parity when Word COM is unavailable.

## Why this matters

The existing summary already failed the run for missing backstage pairs, placeholder captures, fallback capture sources, and missing required pages. The new structured field lets automation and planners check readiness without parsing Markdown, while the Markdown table makes the same failures directly actionable for reviewers.

## Remaining blockers for real capture production

- The paired runner now produces trusted WPF/Avalonia backstage evidence rows locally under `freew-fidelity-corpus/runs/...`; keep that runner output as the required artifact before claiming a Backstage print/export visual slice ready.
- MS Word baseline comparison still depends on Word COM availability when using `tools/Run-FreeWWordBaselineEvidence.ps1` without `-AllowMissingWord`.
- `tools/Run-FreeWWordBaselineEvidence.ps1` can still document Word COM unavailability with software-rendered WPF fallback output, but that fallback output is no longer trusted as backstage print/export visual evidence.
- Native printer selection remains host-specific; the authoritative cross-host evidence path is still Print Preview plus PDF export raster evidence.
