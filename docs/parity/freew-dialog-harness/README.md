# FreeW Dialog Visual Harness

This evidence bundle is generated by `freew/tools/FreeW.DialogVisualHarness` from the current WPF and Avalonia source trees. The source-hashed inventory contains only applicable lifecycle and tab states for each dialog, pane, overlay, and Backstage surface.

## Run

```powershell
dotnet run --project freew/tools/FreeW.DialogVisualHarness/FreeW.DialogVisualHarness.csproj -c Release -- inventory --repo-root . --output docs/parity/freew-dialog-harness
dotnet run --project freew/tools/FreeW.DialogVisualHarness.Wpf/FreeW.DialogVisualHarness.Wpf.csproj -c Release -- --inventory docs/parity/freew-dialog-harness/freew_dialog_evidence_inventory.json --output artifacts/freew-dialog-harness/phase2-seven-final-wpf
dotnet run --project freew/tools/FreeW.DialogVisualHarness.Avalonia/FreeW.DialogVisualHarness.Avalonia.csproj -c Release -- --inventory docs/parity/freew-dialog-harness/freew_dialog_evidence_inventory.json --output artifacts/freew-dialog-harness/phase2-seven-final-avalonia
dotnet run --project freew/tools/FreeW.DialogVisualHarness/FreeW.DialogVisualHarness.csproj -c Release -- compare --inventory docs/parity/freew-dialog-harness/freew_dialog_evidence_inventory.json --wpf artifacts/freew-dialog-harness/phase2-seven-final-wpf/wpf_dialog_capture_manifest.json --avalonia artifacts/freew-dialog-harness/phase2-seven-final-avalonia/avalonia_dialog_capture_manifest.json --output docs/parity/freew-dialog-harness
dotnet run --project freew/tools/FreeW.DialogVisualHarness/FreeW.DialogVisualHarness.csproj -c Release -- compare --inventory docs/parity/freew-dialog-harness/freew_dialog_evidence_inventory.json --wpf artifacts/freew-dialog-harness/phase2-seven-final-wpf/wpf_dialog_capture_manifest.json --avalonia artifacts/freew-dialog-harness/phase2-seven-final-avalonia/avalonia_dialog_capture_manifest.json --output docs/parity/freew-dialog-harness --check
```

`--check` is supported by both `inventory` and `compare` and validates the tracked JSON, Markdown, HTML, and freshness sidecar byte-for-byte. Avalonia uses the Skia renderer with `UseHeadlessDrawing = false` and captures compositor frames through `CaptureRenderedFrame`. Every Avalonia full image and target crop must pass opacity, near-black, dominant-color, color-variation, luminance-range, and painted-bounds gates before its manifest row can be `captured`.

The comparison normalizes both sides to 96-DPI logical target dimensions, emits target crops and heatmaps, and reports focus/default/cancel/action-order metadata independently from image metrics. Desktop DPI is recorded as environment metadata, not used as a parity exemption.

## Current Run

- Inventory: 156 routes and 457 host-specific scenarios: 186 WPF authority states and 271 Avalonia states.
- WPF: 186/186 app-owned captures, with 186 full PNGs and 186 target crops.
- Avalonia: 271/271 app-owned Skia captures, with 271 full PNGs and 271 target crops; all 542 images pass pixel-content validation.
- Seven WPF-authority product routes: 24/24 Avalonia states captured across Compare Documents, Legal Notices, Password Prompt, Screen Clip Overlay, Symbol Picker, Table Formula, and Table Properties.
- Comparison: 176 genuine visual mismatches, 1 visual pass, 0 semantic-only mismatches, 94 Avalonia extensions, and 9 state-not-applicable rows. There are zero host-missing, product-gap, invalid-content, hook-required, or surface-level native-picker limitation rows.

The semantic-only row in the pre-normalization run was `screen-clip-overlay.open`: WPF exposed an empty focused automation ID while Avalonia exposed `null`; neither app-owned overlay has a focusable control. The harness now normalizes blank focus IDs to `null`, so the regenerated final report records this paired overlay as a visual pass rather than an unexplained semantic mismatch.

Native file-picker activation and print submission remain external interaction boundaries. Their app-owned Backstage and CUPS surfaces are captured here; the harness does not invoke the OS picker or submit a print job.
