# FreeW Dialog Visual Harness

This evidence bundle is generated by `freew/tools/FreeW.DialogVisualHarness` from the current WPF and Avalonia source trees. The route inventory is source-hashed and contains a row for each host, dialog/pane/overlay family, and exact lifecycle state: `initial`, `populated`, `validation-error`, and relevant tab states.

## Run

```powershell
dotnet run --project freew/tools/FreeW.DialogVisualHarness -- inventory --repo-root . --output docs/parity/freew-dialog-harness
dotnet run --project freew/tools/FreeW.DialogVisualHarness.Wpf -- --inventory docs/parity/freew-dialog-harness/freew_dialog_route_inventory.json --output artifacts/freew-dialog-harness/wpf
dotnet run --project freew/tools/FreeW.DialogVisualHarness.Avalonia -- --inventory docs/parity/freew-dialog-harness/freew_dialog_route_inventory.json --output artifacts/freew-dialog-harness/avalonia
dotnet run --project freew/tools/FreeW.DialogVisualHarness -- compare --inventory docs/parity/freew-dialog-harness/freew_dialog_evidence_inventory.json --wpf artifacts/freew-dialog-harness/wpf/wpf_dialog_capture_manifest.json --avalonia artifacts/freew-dialog-harness/avalonia/avalonia_dialog_capture_manifest.json --output docs/parity/freew-dialog-harness
```

`--check` is supported by both `inventory` and `compare`. The comparison normalizes both sides to 96-DPI logical target dimensions, emits dialog target-subtree crops and heatmaps when both real PNGs exist, and reports semantic metadata independently from image metrics. Desktop DPI is recorded in each capture manifest and is not used as a blanket parity exemption.

## Current Run

- Inventory: 155 routes and 493 host-specific scenario states.
- WPF: 14 real app-owned PNGs from `Page Setup` and `Options`, including initial, populated, validation/error, and tab states.
- Avalonia: no PNG claimed. The machine's Avalonia headless renderer returned zero-byte output for the six shared target states; no placeholder was substituted.
- Comparison: 12 `avalonia-headless-render-unavailable`, 141 `capture-hook-required`, 9 `native-picker-platform-limitation`, and 169 `not-implemented-on-host` rows. There are no visual parity passes or genuine visual mismatches because no pair has two real PNGs.

## Exact Hook Handoff

No existing app-owned file was modified for capture. To unlock the six shared Avalonia captures, a temporary test-only adapter hook is needed after the dialog `Show()` plus layout pass: expose the rendered top-level surface to the adapter so an active desktop/headless backend can return a non-zero PNG at the fixed 560x600 logical target. The hook must also expose the target subtree bounds for panes/overlays and preserve focus/default/cancel/action-order metadata. The adapter must fail closed on zero bytes and must not synthesize a placeholder. The hook should be removed or replaced when the foreground capture path lands.

The remaining `capture-hook-required` rows need route-specific app-owned constructors or command callbacks, especially dialogs that depend on a live shell/editor. Native file/printer pickers remain platform evidence and are not inferred from semantic checks. Page-layout-owned files were not changed.
